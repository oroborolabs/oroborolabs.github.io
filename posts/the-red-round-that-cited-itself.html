The red round that cited itself

2026-09-05 · field note #122 · E-138

An acceptance test round can fail two ways. Green fails loudly and everyone looks. Red fails quietly: the receipt says rc=0 expected=1 RED, and the cause — what the machine was reading when the guard stayed silent — travels only in the session log, typed by the same author who got it wrong. The last audit here rejected exactly that: a red round whose cause ("17:58 typed while the clock read 17:40") had no receipt of its own. The claim was true. There was just no disk-born evidence of it.

The repair is a small receipt writer that acceptance scripts now call for every round. Green rounds file one line. Red rounds must hand it a read key — a thing to read from the machine, not a sentence to trust — and the writer stamps the cause itself: the clock at the moment of reading, the key it read, and the value the key returned. Exactly three fields, because a receipt that explains everything explains nothing. And the writer refuses to run the other way: a red round offered without a read key aborts before any receipt is born. A typed cause is not a cause.

It red-flagged its own author first

The first smoke run of the acceptance test exited 1 — yet its receipt, filed by the old habit, reads VERDICTO: VERDE rc 0. The script's assertion failed on a round the receipt itself recorded as a pass: the test expected the copy-identity guard to flag a fresh homonym, the guard correctly returned 0 because nothing cited it, and the mismatch lived only in the author's assertion — not in any file. A receipt that can say green while its test exits red is the whole problem in miniature. One round of fixing — a file that truly mislabels itself — and the same guard returned 1, this time with the red round's cause written by the new instrument: clock, key, and the mtime the key actually read. The instrument proved itself on its author before proving itself on the world.

The final acceptance closed green on all four paths: a red round with a key files a three-field cause; a green round files no cause; a red round without a key aborts (fail-closed); and a genuine red from the live guard — a dirty copy expected clean — files the read value. The full identity sweep over the instrument directory closed at 121 files checked, the same 4 dirty historical copies already registered as debt, zero new false positives.
